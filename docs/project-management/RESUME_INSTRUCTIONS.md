1. Open the connected GitHub repository `lotussavy/lotussavy.github.io` and inspect the latest `main` state (or stated working branch).
2. Read [PROJECT_STATE.md](PROJECT_STATE.md), then [MASTER_BLUEPRINT.md](MASTER_BLUEPRINT.md).
3. Read the relevant sections of [TASKS.md](TASKS.md), [DECISIONS.md](DECISIONS.md), [VALIDATION.md](VALIDATION.md), and the latest [CHANGELOG.md](CHANGELOG.md).
4. Inspect relevant source files, git changes and test evidence; do **not** assume a status is accurate without checking.
5. State the active milestone, confirmed completed work, open blockers, and next exact action.
6. Make only changes justified by the active task and its dependencies; retain mathematical rigor, accessibility, and existing site behavior.
7. For substantive sessions, update PROJECT_STATE, TASKS, VALIDATION, DECISIONS (if needed), and CHANGELOG, with the corresponding commit or branch reference.

## Rules
- Trust verified repository state and tests over conversational recollection.
- Do not invent proof of optimality, test passes, deployed pages, or progress percentages.
- Separate educational synthetic examples from research-grade claims.
- Record meaningful architecture changes as ADRs.
- Never put secrets, confidential data, private research datasets, or personal information in this public GitHub repository.
- A conversation ending does not imply background work continues.
