## Documentation precedence
Actual repository code and passing tests establish implementation facts. PROJECT_STATE is the concise handoff; MASTER_BLUEPRINT establishes approved scope; DECISIONS records rationale; TASKS tracks verified completion. When sources conflict, inspect code/tests and reconcile the files.

## Safety
Never commit credentials, confidential material, unapproved unpublished research, private datasets, or personal data. Excluding content from Jekyll output does not restrict access to a public GitHub repository.

## Checkpoint discipline
At the end of each substantive session, record the task ID, commit SHA or branch, changes, verification results, blockers, next concrete action, and update date. Avoid invented progress percentages.
