The foundation release

The Optimization Learning Lab is created and maintained by Kamal Acharya. This first public package covers OPT-001–004, the Profit Playground, Decision Model Builder, Feasibility Explorer, Optimality Comparator, glossary and local search. Begin with the beginner guide.

Models, coefficients and financial values are original synthetic teaching examples. Results describe the stated mathematical model and supported input ranges. They are not empirical fleet data, operational recommendations or published research findings. Later curriculum levels are marked as planned on the homepage.

How content is checked

  1. Explanation: check the learning objective, prerequisites, terminology, units, worked example and knowledge-check answers. Primary references are listed in each lesson; original examples are labeled.
  2. Mathematics: compare outputs with independent calculations. The fleet model uses exhaustive enumeration; the feasibility model uses independent boundary intersections and exact arithmetic; the optimality activity uses analytic bounds and a separate piecewise calculation. A sampled graph alone does not prove a continuous optimum.
  3. Implementation: run model, Python, generated-index, link, browser and accessibility checks before publication. Exercise boundaries, empty feasible sets, tied optima, reset and error states where applicable.
  4. Release: verify the deployed pages, record the source revision and review results, and keep an explicit list of remaining limits. A reviewed date records the scope of a completed check.

Content and code are developed with AI assistance. The recorded review combines assisted editorial inspection, independent mathematical implementations, automated checks and direct browser observation. It does not constitute an independent external peer review or a study of learning outcomes with students.

Read the foundation release review and its evidence. The project records retain earlier lesson reviews, decisions and changes.

Accessibility and fallbacks

The release review checks keyboard access, labels and result summaries, visible focus, contrast, text alternatives, rendered equations with assistive MathML, reduced motion and narrow layouts. Automated WCAG-tagged axe checks complement the browser review. Dedicated NVDA, VoiceOver or Orca compatibility testing remains an open follow-up; these checks do not establish full WCAG conformance or compatibility with every assistive technology.

The lesson text, glossary, worked examples and browse links are available without JavaScript. Interactive controls and local search require JavaScript. Equations load MathJax from a public CDN; if it is unavailable, the mathematical source and neighboring explanations remain in the page. Please report an access barrier using the correction route below.

Report a correction or access problem

Email a correction

This opens your email app with a reporting template. You can also write directly to {{ site.author.email | escape }}. Include the page URL or lesson ID, steps or input values, the expected and observed result, and an explanation or source for a proposed mathematical correction. For access problems, include your browser and assistive technology if relevant. Send only information needed to explain the issue.

Reports go to the maintainer for review. Confirmed corrections are recorded with their affected example or page and verification evidence. There is no automatic submission, response-time guarantee or claim that an issue is fixed before it is checked.

Citing, versions and reuse

Cite the specific lesson title and stable URL, its last-reviewed date, and your access date. For a reproducible result, also record the activity inputs and the repository commit used. Source history and the release review identify the checked revision.
